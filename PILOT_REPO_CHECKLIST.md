# Pilot Repo Checklist

Use this when applying the template to one real repository.

## Choose the repo

- active development
- repeated task types
- clear build, test, and lint commands
- enough team interest to refine the workflow

## Before writing anything

- identify the top 3 repeated engineering workflows
- identify the highest-risk file paths
- identify the minimal verification path
- collect 5-10 real past tasks

## `AGENTS.md`

- add repo mission
- add read-first files
- add exact commands
- add a codebase map
- add working and verification rules
- add escalation rules
- remove fluff

## Skills

Create 3 first:

- bug-fix
- PRD-to-plan
- prompt-change-with-eval

Then replace or add based on actual task distribution.

## Hooks

Start with 2 or 3 only:

- forbidden path or secret protection
- verification reminder
- diff-size warning if scope creep is common

## Memory

Record only:

- durable team preferences
- environment quirks
- prior decisions worth carrying across tasks

## Eval harness

- define 5-10 real tasks
- standardize task format
- define pass/fail checks
- record baseline results

## Success criteria after 2 weeks

- team repeats fewer instructions manually
- Codex tasks are more precise
- at least 3 workflows are skill-backed
- risky paths have guardrails
- prompt changes are tested rather than judged anecdotally
